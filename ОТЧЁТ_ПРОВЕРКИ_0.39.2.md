## Фактически выполнено

Собран полный проект на основе `Trest-Systems-v0.39.1-FULL-AUTO-INSTALL-PREBUILT.zip` с SHA-256 `8d6d15881aeb774d53372b69fdb52981200b58d60f484f63577dd14c0c7d1945`. Дополнительно собран Windows/amd64 `trest-install.exe`, запускающий установку через PowerShell/WSL2. Бинарник `trestctl` теперь отдельный, а не копия `trest`. Сборка выполнена Go 1.23.2; это ограничение среды, а не рекомендация использовать старый компилятор в production.

## Что исправлено

Единый мигратор использует строковое имя файла и контрольную сумму; запуск SQL без параметров передаётся простым протоколом libpq, а параметризованные запросы остаются параметризованными. Уже применённые миграции пропускаются после проверки SHA-256; ошибки запросов не скрываются. API с `SKIP_API_MIGRATIONS=1` проверяет актуальность схемы вместо безусловного пропуска.

Установщик не исполняет `.env` как shell-код, сохраняет существующие секреты и дополнительные настройки и не копирует случайный `.env` поверх рабочего. Пароль БД проверяется по TCP. Несовпадение не маскируется: синхронизация требует явного флага. Перед изменением существующего развёртывания создаётся SQL/config backup, а несовместимый legacy-магазин блокирует автоматическое обновление.

Магазин изолирован в PostgreSQL-схеме `marketplace`, поскольку старые integer IDs и поля `users/orders` несовместимы с UUID-схемой Go API. Существующие данные автоматически не переименовываются и не удаляются. Пароль действующего администратора больше не сбрасывается при каждом старте. Для новой установки создаются отдельные начальные учётные данные.

Порты проверяются с учётом владельца Docker Compose; чужие контейнеры не останавливаются. Ollama, WebUI и MinIO доступны только через loopback. В HTTP-режиме 443 не публикуется. Healthchecks проверяют HTTP, а не только наличие бинарника. WebUI использует локальный Ollama для embeddings, запускается в offline-режиме, требует авторизацию и не сбрасывает настройки на каждом старте. Внешние маршруты frontend/Python API согласованы.

Основные Linux/Windows и вложенные установочные входы направлены в единый установщик; сборка и упаковка больше не используют старый путь `linux-amd64` и не пытаются собрать libpq-программы с отключённым CGO. Исторические GPU-инструменты сохранены, но автоматически не запускаются и не входят в проверку новой установки.

## Что не проверено и не включено

**Docker daemon и PostgreSQL server в среде сборки отсутствуют.** Поэтому не выполнены новый полный Compose-запуск, установка на чистой машине, повторное развёртывание, реальный SQL backup/restore, пользовательский E2E, весь BIM/заказы/роли/AI, внешняя доступность и доверенный TLS/браузер. Успешные старые серверные логи v0.39.1 не заменяют проверку новой v0.39.2.

Новая frontend-сборка после обновления Node/Next и полноценный Python runtime с pinned зависимостями не проверены: загрузка зависимостей была недоступна. Go использует унаследованные локальные compatibility implementations, а не полные upstream pgx/Cobra/YAML. Актуальный аудит зависимостей/CVE также не завершён.

**Docker-образы и многогигабайтные веса моделей в ZIP не включены.** Обычная первая установка требует интернета. Для отдельного офлайн-пакета предусмотрен `scripts/release/export-offline.py`; он экспортирует реальные образы и Ollama-модели с подготовленного хоста. Экспортёр в текущей среде не запускался.

SQL backup/restore не заменяет согласованный полный backup MinIO, uploads, WebUI и конфигурации. Не заявляется ни «ошибок в продукте нет», ни «продукт на 100% готов».

## Установка

На **новом** Linux x86_64 сервере после распаковки:

```bash
cd Trest-Systems-v0.39.2
sudo bash install.sh --tls off --non-interactive
```

На уже работающем `217.198.12.184` **не распаковывать поверх проекта и не запускать обновление без плана переноса legacy-данных**. См. `docs/install/UPGRADE_RU.md`. Новый пакет и этот отчёт не изменяли сервер или GitHub.

Публичные HTTP-запросы не зашифрованы. До production-доступа требуется проверенный HTTPS, смена ранее опубликованных секретов и полноценная функциональная/безопасностная приёмка.
