# Trest Systems — Prior-Art Search Checklist

## Цель
Не доказывать новизну заранее, а системно проверить, какие признаки Trest Systems уже раскрыты и какие комбинации требуют дополнительного анализа.

## Поисковые семейства

1. construction management + BIM + procurement
2. BIM + quantity takeoff + estimate version
3. construction marketplace + contractor selection + supplier selection
4. software agent + tool allowlist + human approval
5. LLM agent + authorization policy + audit
6. local LLM + on-premise construction/project data
7. AI audit + model version + prompt/output lineage
8. immutable estimate version + order linkage
9. CAD/DXF + project management integration
10. GOST/CAD + construction workflow
11. QLoRA/LoRA enterprise domain adaptation + local inference
12. self-hosted orchestration + local AI

## Для каждого документа фиксировать

- publication number;
- title;
- applicant/assignee;
- inventors;
- priority date;
- filing date;
- publication date;
- legal status;
- independent claims;
- relevant dependent claims;
- relevant figures;
- matching Trest feature IDs F01–F15;
- differences;
- technical effect disclosed;
- preliminary relevance: high/medium/low.

## Важное различие

Prior-art search на новизну и freedom-to-operate analysis — разные задачи. Даже если конкретная комбинация признаков окажется новой для патента, отдельные компоненты или способы реализации могут подпадать под чужие действующие права.

## Официальный ориентир

WIPO указывает, что патентоспособность зависит от юрисдикции и обычно включает novelty, inventive step/non-obviousness, industrial applicability/usefulness и допустимость объекта. Для software-related inventions требования существенно различаются по странам.
