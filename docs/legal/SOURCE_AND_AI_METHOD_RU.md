# Trest Systems — метод разработки и источники

## 1. Назначение

Документ фиксирует, каким образом формировался проект, чтобы отделить собственную разработку от библиотек, инфраструктуры и AI-assisted материалов.

## 2. Методы разработки

Проект строится как monorepo/self-hosted система с единым Go-контуром, API, PostgreSQL/Redis/MinIO, frontend и локальным AI-контуром. В проектной документации закреплено требование не добавлять обязательные AWS/Azure/GCP зависимости без отдельного архитектурного решения. fileciteturn16file1L122-L133

Разработка ведётся итерациями (Stage 0, Stage 1, …). Для каждой стадии ведутся отчёты и continuity-файлы.

## 3. AI-assisted development

AI использовался как инструмент проектирования, анализа, генерации чернового кода, документации и тестовых материалов. Существенные результаты должны проходить человеческую проверку и попадать в Git как часть контролируемой разработки.

В журнале проекта зафиксированы AI-сессии и изменения, а также правило сохранять состояние репозитория и результаты проверок. fileciteturn17file0L43-L57

## 4. Внешние источники

При разработке использовались документация и open-source библиотеки, перечисленные в `THIRD_PARTY_LICENSES.md`. Наличие ссылки на библиотеку не означает копирования её исходного кода в Trest Systems.

## 5. Сохранённые исходные подпроекты

Проект содержит `magasin-777`, `proektirovka-sdaniy`, `super-sistema` и `trest-installer`. Их происхождение должно рассматриваться отдельно при due diligence.

## 6. Правило для будущих изменений

Любой новый внешний код должен:
1. иметь зафиксированный источник;
2. иметь определённую лицензию;
3. быть совместимым с моделью распространения;
4. попасть в SBOM/license inventory;
5. иметь сохранённый LICENSE/NOTICE, если это требуется.
