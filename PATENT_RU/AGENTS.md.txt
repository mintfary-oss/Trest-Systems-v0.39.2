**Подробный план создания единого Go‑приложения‑установщика для экосистемы Trest‑sistems**  

---

### 1. Общая архитектура

| Компонент | Описание | Технология |
|-----------|----------|------------|
| **Docker‑образ** | Самодостаточный контейнер, содержащий все зависимости, Go‑бинарник и скрипты инициализации. | Dockerfile (Alpine + golang) |
| **Go‑ядро** | Основное приложение, отвечающее за: <br> • Скачивание и проверку кода из репозитория <br>• Сборку проекта <br>• Диагностику (логи, порты, аудит) <br>• Вывод отчётов | Go 1.22 |
| **CLI‑интерфейс** | Пользователь взаимодействует через терминал: `trest-installer run`. | Cobra (или `flag`) |
| **Веб‑интерфейс** | Статическая страница, отображающая текущий статус, журнал и отчёт о проверках. | Go `net/http` + шаблоны HTML (embed) |
| **Хранилище состояния** | Файл `.trest_state.json` в рабочей директории, где фиксируются выполненные шаги, найденные ошибки и текущий прогресс. | JSON + `os.UserCacheDir` |

### 2. Подготовка репозитория

1. **Клонирование**  
   ```bash
   git clone https://github.com/mintfary-oss/Trest-sistems.git
   cd Trest-sistems
   ```
2. **Получение токена** – токен никогда не хранится в репозитории; при необходимости передаётся только через переменную окружения `GITHUB_TOKEN`.  
3. **Проверка ветки/тега** – в конфиге (`config.yaml`) задаём ветку/тег, который будет собираться (по‑умолчанию `main`).  

---

### 3. Сборка Go‑приложения

1. **Модуль** – `go.mod` с зависимостями: `github.com/spf13/cobra`, `github.com/go-git/go-git/v5`, `github.com/docker/docker/client`, `golang.org/x/crypto/ssh`.
2. **Основные пакеты**  

   * `cmd` – CLI‑команды (`run`, `status`, `audit`).  
   * `internal/git` – функции клонирования, проверка обновлений.  
   * `internal/build` – вызов `go build` внутри контейнера.  
   * `internal/diagnostics` – проверка логов, портов, доступности сервисов.  
   * `internal/report` – формирование JSON‑ и HTML‑отчётов.  

3. **Сборка в Docker**  

   ```Dockerfile
   FROM golang:1.22-alpine AS builder
   WORKDIR /app
   COPY . .
   RUN go build -o trest-installer ./cmd/trest

   FROM alpine:3.20
   RUN apk add --no-cache ca-certificates
   COPY --from=builder /app/trest-installer /usr/local/bin/
   COPY web/ /usr/local/share/trest/web/
   ENTRYPOINT ["/usr/local/bin/trest-installer"]
   ```

   *Контейнер* запускается без необходимости доступа к облачным сервисам – все нужные артефакты находятся внутри образа.

---

### 4. Пошаговый процесс установки (что будет делать приложение)

1. **Инициализация** – чтение/создание `config.yaml` и `state.json`.  
2. **Клонирование репозитория** (или `git pull` при повторных запусках).  
3. **Сборка проекта** (`go build ./...`) внутри контейнера; вывод ошибок в `state.json`.  
4. **Проверка логов** – читаем файлы из `./logs/` (если они есть). При наличии `ERROR`/`WARN` сразу выводим их в терминал и записываем в отчёт.  
5. **Проверка портов**  

   ```go
   func freePort(p int) bool {
       ln, err := net.Listen("tcp", fmt.Sprintf(":%d", p))
       if err != nil { return false }
       _ = ln.Close()
       return true
   }
   ```
   * Если порт занят – выводим рекомендацию (освободить/изменить).  
   * Если свободен – сохраняем в `state.json`.  

6. **Запуск приложения** – `exec.Command("./bin/trest-app", "--port", port).Start()`.  
7. **Аудит** – проверяем, что процесс жив, что открыты необходимые сокеты, читаем метрики (CPU/Memory) через `runtime`‑пакет.  
8. **Формирование отчёта**  

   * `report.json` – машинночитаемый.  
   * `report.html` – статический, доступный по `http://localhost:<auditPort>/report`.  

9. **Вывод в терминал** – «Установка завершена, все тесты прошли», либо список найденных проблем с рекомендациями.  

---

### 5. Автоматическое продолжение после ошибки

1. При любой нефатальной ошибке (`state.json` фиксирует `last_step`).  
2. При следующем запуске приложение читает `last_step` и **продолжает** с него (например, если сборка не удалась – повторно запустит только сборку).  
3. При фатальных ошибках (недоступный порт, отсутствие прав) приложение выводит инструкцию и **завершается**, оставляя состояние для ручного исправления.

### 6. Мониторинг репозитория

| Событие | Действие |
|--------|----------|
| **push** в выбранную ветку | Через `git remote update` обнаруживаем новый коммит → автоматически запускаем процесс с шага 3. |
| **cron** (каждые 5 мин) | Периодическая проверка `git fetch` → если изменения – запуск. |
| **webhook** (опционально) | Приём POST‑запроса от GitHub → мгновенный старт. |

*Все проверки сопровождаются логами в `state.json`.*

Ниже подробный план, как именно это реализовать технически.

---

### 1. Концепция объединения
Вместо того чтобы запускать два разных процесса, мы создаем одно приложение, которое работает в режиме **Менеджера (Оркестратора)**. 

**Схема работы:**
`Пользователь` $\rightarrow$ `Go-Installer (Менеджер)` $\rightarrow$ `Запуск Модуля А` + `Запуск Модуля Б` $\rightarrow$ `Общий Веб-интерфейс`.

---

### 2. Техническая реализация объединения

#### А. Объединение кода (Структура проекта)
Вы переносите код обоих приложений в разные пакеты одного проекта:
```text
/trest-sistems
  ├── cmd/
  │    └── main.go          # Точка входа (Менеджер)
  ├── internal/
  │    ├── app1/            # Весь код первого приложения
  │    │    └── service.go
  │    ├── app2/            # Весь код второго приложения
  │    │    └── service.go
  │    ├── installer/       # Логика установки, Docker, порты
  │    ├── audit/           # Проверка логов и здоровья
  │    └── web/             # Общий веб-интерфейс
  └── config.yaml           # Общие настройки портов для обоих приложений
```

#### Б. Запуск в разных потоках (Goroutines)
Чтобы два приложения работали одновременно внутри одной программы, каждый из них должен быть обернут в функцию и запущен в отдельном потоке (`goroutine`):

```go
func main() {
    // 1. Сначала работает установщик (проверка портов, логов)
    installer.RunChecks()

    // 2. Запуск Приложения 1 в фоне
    go app1.StartService(config.Port1)

    // 3. Запуск Приложения 2 в фоне
    go app2.StartService(config.Port2)

    // 4. Запуск общего Веб-интерфейса мониторинга (основной поток)
    web.StartInterface(config.AuditPort)
}
```

---

### 3. Интеграция функций управления (по вашему запросу)

#### 1. Система "Памяти" (Продолжение с места остановки)
Чтобы программа знала, что сделано, создается файл `state.json`.
- Перед каждым действием (клонирование $\rightarrow$ сборка $\rightarrow$ запуск App1 $\rightarrow$ запуск App2) программа пишет в файл: `"last_completed_step": "build"`.
- При запуске программа читает файл и перепрыгивает через уже выполненные этапы.

#### 2. Проверка портов и логов
Перед тем как вызвать `go app1.StartService()`, менеджер делает следующее:
- **Порты:** Пытается открыть порт. Если `net.Listen` возвращает ошибку "address already in use", программа пишет в терминал: `Ошибка: Порт 8080 занят. Освободите его или измените в config.yaml`.
- **Логи:** Менеджер запускает оба приложения, перенаправляя их вывод (`stdout/stderr`) в общий файл логов. Если в логе появляется слово `FATAL` или `ERROR`, менеджер мгновенно дублирует эту строку в терминал пользователя.

#### 3. Единый веб-интерфейс
Вместо двух разных админок создается одна на Go (с использованием `html/template`), которая:
- Показывает статус: `App1: RUNNING`, `App2: ERROR`.
- Выводит последние 20 строк из общего файла логов.
- Показывает отчет об аудите (время работы, потребление памяти).

1. **Этап Рефакторинга:** Перенести код приложения №1 и приложения №2 в пакеты `internal/app1` и `internal/app2`.

3. **Этап Оркестрации:** Написать `main.go`, который по цепочке запускает: `Проверка портов` $\rightarrow$ `Проверка логов` $\rightarrow$ `Запуск App1` $\rightarrow$ `Запуск App2` $\rightarrow$ `Запуск Web-UI`.
4. **Этап Состояний:** Реализовать запись прогресса в `state.json` для возможности доустановки.
5. **Этап Контейнеризации:** Создать один `Dockerfile`, который собирает этот объединенный бинарник и запускает его.

**Результат:** Вы получаете один исполняемый файл (бинарник), который при запуске ведет себя как полноценный установщик, проверяет сервер, поднимает сразу два сервиса и дает вам одну ссылку на веб-панель управления всем этим процессом.
