# Trest Systems — подробная инструкция пользователя

## 1. Что это за программа

**Trest Systems** — self-hosted единая цифровая платформа для строительных компаний, подрядчиков и поставщиков. В одной системе объединяются:

- проекты и конструктор объектов;
- сметы и версии смет;
- заказы и этапы выполнения;
- подрядчики и проверка компетенций;
- поставщики, предложения и остатки;
- рейтинги и репутация;
- AI-модели и AI-ассистенты;
- агенты с инструментами и правами;
- подготовка датасетов и обучение LoRA/QLoRA;
- DXF/GOST проектирование;
- локальная AI-инфраструктура Ollama/Open WebUI;
- 3D/BIM (следующий этап развития).

Система рассчитана прежде всего на локальное/self-hosted размещение. Критические юридические, финансовые и договорные операции не должны изменяться AI автономно.

## 2. Как устроена система

Основные компоненты:

- `cmd/trest` — основной CLI;
- `cmd/trestctl` — управление установкой/состоянием;
- `cmd/api` — единый Go API;
- `cmd/worker` — фоновые операции;
- `internal/` — бизнес-логика;
- PostgreSQL — данные;
- Redis — очередь/кэш;
- MinIO — объектное хранилище;
- Ollama/Open WebUI — локальный AI runtime;
- Next.js/FastAPI — сохранённые специализированные части marketplace;
- Nginx — единая точка входа.

## 3. Быстрая установка production

Для production-релиза рекомендуется использовать **предсобранный release bundle**, а не компилировать Go на сервере.

Идеальная схема:

1. Скачать архив релиза.
2. Распаковать.
3. Проверить `.env`.
4. Выполнить `./trestctl install` или штатный release installer.
5. Запустить стек.
6. Проверить `/health` и `/ready`.

Production release должен содержать заранее собранные Go-бинарники и/или заранее собранные OCI/Docker images. Сервер установки не должен запускать `go build`.

## 4. Разработка

Для разработки допустимо:

```bash
go test ./...
go build ./...
go vet ./...
```

Для production эти команды выполняются заранее в CI/release environment.

## 5. Основной CLI

```text
 trest run       запуск/оркестрация
 trest status    состояние последнего запуска
 trest audit     аудит
 trest generate  генерация DXF/GOST
 trestctl        управление установкой
```

Точный набор команд проверяется через `--help` конкретного релиза.

## 6. Работа с AI

Поток работы:

```text
Dataset → Dataset Version → Training Job → Evaluation → Model Version → Promotion → Agent
```

AI-запросы сохраняют вход, результат, модель/версию и служебный аудит.

## 7. Создание ассистента

1. Зарегистрировать модель.
2. Создать prompt/template.
3. Создать датасет.
4. Подготовить JSONL.
5. Создать training job.
6. Запустить LoRA/QLoRA на GPU-сервере.
7. Выполнить evaluation.
8. При прохождении порога опубликовать model version.
9. Создать/обновить agent.
10. Выдать только необходимые tools/permissions.
11. Для опасных действий включить human approval.

## 8. Правило безопасности AI

AI является рекомендательной системой и исполнительным помощником только в пределах явно выданных прав. Он не получает автоматического права менять юридические, финансовые или договорные данные.

## 9. Резервное копирование

Production должен регулярно сохранять PostgreSQL и MinIO. Backup/restore должен тестироваться отдельно; наличие файла backup само по себе не считается проверенным восстановлением.

## 10. Обновление

Перед обновлением:

1. backup;
2. проверить release manifest/checksum;
3. остановить только необходимые сервисы;
4. применить миграции;
5. проверить health/readiness;
6. проверить критические API;
7. сохранить предыдущий release для rollback.

## 11. Диагностика

При проблеме собрать:

- версию release;
- `trest status`;
- health/readiness;
- последние логи API/worker;
- состояние PostgreSQL/Redis/MinIO;
- статус Ollama;
- migration status.

Не удалять volumes или базу данных для исправления проблемы без отдельного подтверждения.
