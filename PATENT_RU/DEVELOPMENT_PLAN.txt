# DEVELOPMENT_PLAN.md — подробный план Trest Systems до завершения проекта

## Принцип
Разработка идет поэтапно. Каждый этап должен закончиться кодом, миграциями (если нужны), API, тестами, документацией и обновлением continuity-файлов. Следующий этап не должен уничтожать функциональность предыдущего.

## Product UI roadmap
В конечном unified Web UI должны быть единый стиль и единый контекст:
- Dashboard
- Projects
- Constructor
- Estimates
- Store/Marketplace
- Orders
- Contractors
- Suppliers
- Ratings
- Documents
- AI
- Agents
- Create Agent
- Models
- Training/Configuration
- 3D/BIM
- Notifications
- Admin

Существующий LocalMarket и Super Sistema не должны визуально оставаться отдельными несвязанными продуктами в финальном пользовательском интерфейсе; интеграционный слой должен привести их к единой навигации и стилю.

## Финальный критерий проекта
Проект считается готовым только когда:
1. все основные доменные этапы реализованы;
2. API и web связаны с единым auth/context;
3. AI интегрирован с контролем прав;
4. 3D/BIM подключен к проектам;
5. backup/restore проверены;
6. monitoring/audit/security закрыты;
7. тесты и runtime validation выполнены на подходящей среде;
8. continuity-файлы позволяют продолжить работу из любого нового ZIP без потери контекста.

## Stage 10 — 3D/BIM
Implement the unified BIM registry, model versioning, element metadata, IFC/glTF/OBJ/DXF exchange job tracking, web 3D viewer integration, architecture-version linkage and planned-vs-actual progress visualization.
